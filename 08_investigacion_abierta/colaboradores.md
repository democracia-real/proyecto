# Colaboradores

## Resumen Ejecutivo

Este documento explica cómo convertirse en colaborador del proyecto Democracia Real y las guías para cada tipo de contribución. El proyecto es abierto: cualquiera puede contribuir en investigación, documentación, revisión, código, diseño o difusión. Se hace referencia al [CONTRIBUTING.md](../CONTRIBUTING.md) para el proceso técnico y al código de conducta.

## Tipos de Contribución

### Investigación

| Actividad | Descripción |
|-----------|-------------|
| **Proponer preguntas** | Sugerir temas de investigación en [preguntas_abiertas.md](preguntas_abiertas.md) o como Issue |
| **Aportar fuentes** | Compartir datos, informes o referencias relevantes |
| **Realizar análisis** | Investigar un tema y documentar hallazgos siguiendo [metodologia_investigacion.md](metodologia_investigacion.md) |
| **Actualizar datos** | Refrescar documentos con datos obsoletos; marcar [PENDIENTE] si no se puede completar |

### Documentación

| Actividad | Descripción |
|-----------|-------------|
| **Mejorar textos** | Corregir errores, clarificar redacción, ampliar secciones |
| **Crear documentos** | Desarrollar nuevos temas siguiendo la plantilla del proyecto |
| **Traducir** | Traducción a idiomas cooficiales (catalán, euskera, gallego) cuando se lance la web pública; priorizando documentos de módulos 01-03 |
| **Estructurar** | Reorganizar contenido para mejor navegación |

### Revisión

| Actividad | Descripción |
|-----------|-------------|
| **Revisar PRs** | Validar contribuciones de otros antes del merge |
| **Verificar fuentes** | Comprobar que las citas son correctas y accesibles |
| **Detectar inconsistencias** | Señalar contradicciones entre documentos |
| **Fact-checking** | Contrastar afirmaciones con datos |

### Código

| Actividad | Descripción |
|-----------|-------------|
| **Web** | Mejorar el sitio estático; ver [07_web_publica_y_transparencia](../07_web_publica_y_transparencia/README.md) |
| **Herramientas** | Scripts de análisis, automatización, APIs |
| **Accesibilidad** | Asegurar cumplimiento WCAG |
| **CI/CD** | Mejorar pipelines de build y test |

### Diseño

| Actividad | Descripción |
|-----------|-------------|
| **UX/UI** | Mejorar usabilidad y estética del sitio |
| **Infografías** | Visualizar datos para comunicación |
| **Identidad** | Logo e identidad visual pendientes de fase de lanzamiento público; contribuciones de diseño bienvenidas |

### Difusión

| Actividad | Descripción |
|-----------|-------------|
| **Compartir** | Dar a conocer el proyecto en redes, comunidades |
| **Comunicar** | Redactar resúmenes, hilos, artículos sobre el proyecto |
| **Conectar** | Acercar a expertos o colectivos que puedan contribuir |

## Cómo Empezar

### Paso 1: Explorar

- Leer el [Readme.md](../Readme.md) principal
- Revisar la [estructura del repositorio](../Readme.md#-estructura-del-repositorio)
- Consultar [preguntas_abiertas.md](preguntas_abiertas.md) para ver qué se necesita

### Paso 2: Elegir una Contribución

| Si quieres... | Empieza por... |
|--------------|----------------|
| Proponer una idea | Abrir un Issue con etiqueta `proposal` o `question` |
| Corregir un error | Buscar Issues con `good first issue` o `bug` |
| Añadir contenido | Crear una rama y un Pull Request |
| Investigar un tema | Consultar [metodologia_investigacion.md](metodologia_investigacion.md) y [fuentes_datos.md](fuentes_datos.md) |
| Revisar | Comentar en PRs abiertos |

### Paso 3: Seguir el Proceso

**Proceso detallado en [CONTRIBUTING.md](../CONTRIBUTING.md):**

1. **Fork** del repositorio
2. Crear **rama** descriptiva (`feature/nombre`, `fix/nombre`)
3. Realizar cambios siguiendo las guías (formato, fuentes, rigor)
4. **Commit** con mensaje claro
5. Abrir **Pull Request** con descripción detallada
6. Esperar **revisión** y responder a feedback
7. **Merge** cuando se apruebe

### Primeras Contribuciones Sugeridas

- Corregir un typo o enlace roto
- Añadir una fuente a [fuentes_datos.md](fuentes_datos.md)
- Completar un [PENDIENTE] con datos verificables
- Proponer una pregunta en [preguntas_abiertas.md](preguntas_abiertas.md)
- Revisar un documento existente y abrir Issue con sugerencias

## Reconocimiento

### Cómo se Reconocen las Contribuciones

| Tipo | Reconocimiento |
|------|----------------|
| **Autoría** | Mención como autor en documentos que crees o lideres |
| **Revisión** | Mención como revisor en el documento |
| **Fuentes** | Crédito en la sección de referencias |
| **Historial** | Tabla de cambios en documentos; commits en Git |
| **Agradecimiento** | Mención general en README o comunicados para contribuciones menores |

### Visibilidad

- Todas las contribuciones son públicas (commits, PRs, Issues)
- El historial de Git preserva la autoría
- Lista de colaboradores visible en web una vez se lance el portal público (ver portal_transparencia.md)

## Código de Conducta

### Principios

El proyecto se rige por los principios del [CONTRIBUTING.md](../CONTRIBUTING.md):

- **Respeto mutuo** en todas las interacciones
- **Debatir ideas, no personas**
- **Aceptar críticas constructivas**
- **Reconocer contribuciones de otros**
- **Mantener confidencialidad** cuando sea necesario

### Expectativas

| Esperamos | No toleramos |
|-----------|--------------|
| Lenguaje respetuoso | Acoso, insultos, ataques personales |
| Argumentos basados en datos | Desinformación deliberada |
| Colaboración constructiva | Saboteo o spam |
| Diversidad de opiniones | Discriminación por ideología, origen, género, etc. |

### En Caso de Conflicto

- Intentar resolver de forma directa y respetuosa
- Si no es posible, contactar a los mantenedores del proyecto
- Canal de contacto para incidencias graves: email dedicado del proyecto (a definir en fase de lanzamiento) + Issues en GitHub con etiqueta `urgente`
